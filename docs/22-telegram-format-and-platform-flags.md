# Telegram Format and Platform Flags

## Active platform policy

| Platform  | Default | Notes                                                                                     |
| --------- | ------- | ----------------------------------------------------------------------------------------- |
| Telegram  | **ON**  | up to 10 selected jobs, information-dense text + company logo media                       |
| Instagram | **ON**  | top 2 media-selected jobs, generated card + caption (+ AutoDM later)                      |
| X         | **OFF** | `FEATURE_X_PUBLISHING_ENABLED=false` by default; code kept, no drafts/publishes while off |
| LinkedIn  | off     | no longer generated by default; historical rows untouched                                 |

## 1. Telegram post format

```
🚨 [TYPE] Hiring Alert

🏢 Company: <company>
💼 Role: <role>
📍 Location: <location>
🎓 Batch / Eligibility: <batch or eligibility>
⏳ Experience: <experience>
💰 Salary / Stipend: <salary/stipend>
🏠 Work Mode: <work mode>

📌 What they're looking for:
• <requirement 1>
• <requirement 2>
• <requirement 3>

🔗 Apply:
<direct application URL>
```

Plain text (no Markdown/HTML parse mode) so no escaping can break the message; all values pass
through an HTML/entity sanitizer. The application URL is never truncated.

## 2. Optional-field rules

Missing fields are omitted entirely (no blank lines, no "N/A"/"Unknown"/"Not Disclosed"):
salary, batch/eligibility, work mode, and experience lines disappear when unavailable. Company
and role render only when present. The requirement block is omitted when no bullets can be built
from stored data. No AI call is made to fill Telegram copy.

## 3. Alert-type precedence (deterministic)

1. `🔥 Mass Hiring Alert` — mass_hiring source + campaign wording (trainee/apprentice/graduate
   engineer/fresher/campus hiring) or 0–1 YOE
2. `🚀 Internship Hiring Alert` — internship employment type or "intern" in the title
3. `🚨 Fresher Hiring Alert` — 2025/2026/2027 grad years, fresher/new-grad/graduate/junior wording,
   or max experience ≤ 1 year
4. `🌍 Remote Hiring Alert` — remote work mode
5. `🏢 Big Tech Hiring Alert` — big_tech source category
6. `⚡ Startup Hiring Alert` — yc/startup source category
7. `🚨 Hiring Alert` — fallback

## 4. Requirement bullets

Built only from stored normalized data: unique skills (up to 5, comma-joined), experience range,
grad-year eligibility, and short qualifications. Deduplicated by normalized text, capped at 4
bullets and 140 characters per bullet; if fewer than 2 bullets exist, individual skills expand
into bullets. No hallucinated requirements.

## 5. Company logo media

Resolution order: the generated Telegram draft's stored media URL (populated at generation time
from the `companies` table `logo_url` when a matching company row exists) → otherwise no logo.
`companies.logo_url` is the approved metadata source; no search engines, no invented logos.

Validation before sending: public http(s) only (private/localhost rejected), 10s timeout,
`image/png|jpeg|webp|gif` content type, ≤10 MB streamed size check; SVG is rejected because
Telegram photos do not support it. Validation failure or a missing logo logs a sanitized warning
and the post publishes as text-only — a logo never blocks a publish.

## 6. Caption-length strategy

- Post ≤ 1024 chars → single `sendPhoto` with the full post as caption.
- Post > 1024 chars → `sendPhoto` with a short caption (leading lines, ≤900 chars) followed by the
  full text via `sendMessage`. The application URL is only in the full message and is never
  truncated.
- Publish events store the primary (photo) message id; two-message sends store
  `"<photoId>+<textId>"` in `external_post_id` for debugging, and `published_url` points at the
  photo message.

## 7. Selection-driven generation

`generatePostsForJob(jobId, { platforms })` now creates drafts only for the requested platforms.
Defaults (`activeGeneratedPlatforms()`) are `telegram` + `instagram`, plus `x` only when the
feature flag is on. `generatePostsForSelection({ telegramJobIds, mediaJobIds })` maps Telegram
Top-10 picks to telegram drafts and media Top-2 picks to instagram (+x when enabled) drafts.
Generation is idempotent per `(job_post_id, platform)`: existing draft/approved/published posts
skip regeneration unless `regenerate: true`. Historical generated posts are never deleted by
normal runs. The manual API endpoint accepts optional `platforms` and `regenerate` fields.

## 8. X feature flag

`FEATURE_X_PUBLISHING_ENABLED=false` (default). When false: no X drafts from default or
selection-driven generation, Buffer publishing returns `skipped` before any provider call, the API
publish endpoint returns that skipped result, and scheduler/publisher paths skip X. When true the
previous X behavior is unchanged. Existing X rows and code remain.
